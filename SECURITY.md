# Security Policy

## Generated-code execution

BenchWolf's mini-HumanEval benchmark evaluates code by executing Python generated by the model under test. This capability is **disabled by default** and requires the explicit `--allow-code-execution` flag.

The implementation uses a temporary working directory, Python isolated mode (`-I`), and a subprocess timeout. These controls reduce accidental interference but **do not create a security sandbox**. Generated code can potentially read or modify files accessible to the current user, make network requests, spawn processes, consume resources, or perform other actions allowed to the BenchWolf process.

Do not enable HumanEval for untrusted model output on a machine containing sensitive data or credentials. For stronger isolation, run BenchWolf inside a disposable VM/container with restricted filesystem, network, and resource permissions.

## Reporting vulnerabilities

Please report a suspected security issue privately to the repository owner instead of opening a public issue with exploit details. Include the affected BenchWolf version, platform, reproduction steps, and impact when possible.
